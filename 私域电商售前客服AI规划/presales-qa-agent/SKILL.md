# Presales QA Agent（私域售前问答客服）

该技能把一份结构化售前知识库（版本/价格/正品/合规/物流支付）编译成一个**确定性、可解释、可回归**的售前问答能力：意图路由 → 合规红线闸 → 转人工判定 → 确定性价格查表 → 知识应答。核心不是"让大模型自由作答"，而是**用规则把高风险动作锁死**，把不确定的一律转人工。

> [!IMPORTANT]
> **三条不可逾越的护栏（RAG 硬约束）**：
> 1. **价格只走确定性查表**——禁止大模型心算/估算/复用会话浮动口径；命中缺货或口径冲突即转人工。
> 2. **正品凭据只来自知识库**——禁止伪造批准文号/注册证书/质检结论/蓝帽子编号，禁止绝对化背书。
> 3. **敏感功效只走白名单**——效果/治疗/禁忌类问题只输出预审核话术或直接转人工，绝不即兴发挥。
>
> **双重输出规范 (Dual Output Standard)**：使用本 Skill 落地时必须**同时**产出：
> 1. **结构化知识库 YAML**：作为引擎输入与存档，价格/承诺/话术逐条可溯源。
> 2. **交互式 HTML Demo**：左侧聊天气泡 + 右侧"透明面板"（命中意图/置信度/知识条目/行动边界决策/是否转人工），供审查与演示。
>
> **输出路径与命名规范 (Output Path & Naming Convention)**：
> - **目录**：业务产物放在以 `[公司/业务名]` 命名的子目录（例如 `私域电商售前客服AI规划/`）。
> - **文件名**：`[公司/业务名]-[内容类型].yaml|html`（例如 `私域电商售前客服-售前问答知识库.yaml`）。
>
> **视觉设计规范 (Visual Design Standard)**：
> - 默认遵循 `ai4pm-skills/design.md`：浅色底 (Light Mode)、容器宽度 **85%**、MiSans 字体优先、品牌色 Starry Blues `#10213E` / Creative Blue `#5DB2E2`。
> - 标准 Header：左侧标题/副标题 + 右侧 `Generated by presales-qa-agent` 与时间戳，底部 `1px` 分割线。
> - Jinja inline style 防坑：动态样式写成 `<div {{ 'style="left:' ~ x ~ 'px;"' }}>`，避免 IDE 误报 CSS 解析错误。

## 问答 SOP（五阶段确定性流水线）

每一阶段对应一个行动边界，保证可解释、可回归：

1. **意图路由**：关键词词典判类 + 置信度打分；`risk` 类命中**优先级最高**（高于 pricing/version 等）。
2. **合规红线闸**：风险意图匹配白名单 `trigger_words` → `safe_reply` 返回预审核话术，或 `response_mode=transfer` 直接转人工（治疗/降血糖等）。
3. **转人工判定**：点名人工、低置信、价格口径冲突、规则外议价、禁忌人群坚持购买 → 生成三段式转人工摘要（关注点 + 已答内容 + 未解决问题）。
4. **确定性价格**：解析 `版本 + 剂量` → 价格表精确查表；缺货档走缺货话术；命中 promo_rule 才算到手价；**绝不心算**；命中冲突标记则转人工。
5. **知识应答**：从知识库检索版本/正品/物流支付口径应答；禁止伪造监管编号与绝对化表述；无命中 → 保守答复 + 转人工。

输出结构：`{intent, confidence, matched_evidence, boundary_decision, need_human, handoff_summary, reply}`。

## 用法

```bash
# 单问作答（打印结构化决策 + 回复）
python3 scripts/answer_engine.py <kb.yaml> --ask "日版 2.5 多少钱？"

# 用测试用例集回归，输出通过率
python3 scripts/answer_engine.py <kb.yaml> --replay <test_cases.yaml>

# 由知识库生成交互式 HTML Demo（浏览器内 JS 引擎镜像本引擎规则）
python3 scripts/build_demo.py <kb.yaml> <output.html>
```

## 交互流程 (Workflow)

1. **知识库抽取**：从政策规则清单 / 本体设计 / 真实会话抽取填充 `knowledge_base.schema.yaml` 的各 section；价格数字必须精确抽取，缺失即标 TODO 并转人工兜底，**不臆造数字**。
2. **引擎回归**：用测试用例集跑 `--replay`，校验价格类数字一致、冲突/治疗/禁忌类转人工、保守话术命中。
3. **Demo 生成**：`build_demo.py` 注入知识库 JSON，产出无后端、离线可演示的交互 Demo。
4. **交付审查**：结构化 YAML + 交互 HTML 双输出，价格/承诺逐条可溯源。

## 核心原则 (Design Principles)

- **确定性 (Determinism)**：价格与优惠只由规则表算出，同一输入永远得到同一输出，价格零幻觉。
- **可溯源 (Traceability)**：每条回复都带 `matched_evidence`，能定位到知识库具体条目/规则。
- **保守优先 (Fail-safe)**：命中不足、置信不够、口径冲突时宁可转人工，绝不硬答。

## QA 清单

- [ ] 三条护栏是否在引擎中硬编码为不可绕过的分支（价格查表 / 凭据来源 / 白名单）
- [ ] 价格类回复数字是否逐字来自知识库 `sku_prices`，无任何心算
- [ ] 日版 2.5 双口径（498/548）是否触发口径冲突转人工
- [ ] 疾病治疗 / 禁忌人群是否走 `transfer` 而非 `safe_reply`
- [ ] 转人工摘要是否为三段式（关注点 + 已答内容 + 未解决问题）
- [ ] Demo 是否 85% 宽度 / Light Mode / MiSans / 标准 Header
- [ ] `--replay` 通过率是否作为 Skill 正确性证据留存
