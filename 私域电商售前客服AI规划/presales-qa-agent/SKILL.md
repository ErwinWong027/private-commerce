# Presales QA Agent（私域售前问答客服）

该技能把一份结构化售前知识库（版本/价格/正品/合规/物流支付）编译成一个**LLM + 工具**的售前问答能力：LLM 负责语义理解与话术生成，`answer_engine.py` 提供确定性工具函数（价格查表/合规判定/库存查询）。核心不是"让大模型自由作答"，也不是"穷举关键词写脚本"，而是**LLM 做语义决策，工具做高风险确定性决策**，把不确定的一律转人工。

> [!NOTE]
> **LLM + 工具架构**：本 Skill 在 IDE 内运行时，LLM 读取知识库后做**语义级意图识别**（非关键词匹配），然后**调用 `answer_engine.py` 的工具函数**获取确定性数据（价格/库存/合规判定），最后基于工具返回值**生成自然话术**。LLM 不可绕过工具直接回答价格/合规类问题。详见 `references/agent_system_prompt.md`。

> [!IMPORTANT]
> **三条不可逾越的护栏（RAG 硬约束）**：
> 1. **价格只走确定性查表**——禁止大模型心算/估算/复用会话浮动口径；命中缺货或口径冲突即转人工。
> 2. **正品凭据只来自知识库**——禁止伪造批准文号/注册证书/质检结论/蓝帽子编号，禁止绝对化背书。
> 3. **敏感功效只走白名单**——效果/治疗/禁忌类问题只输出预审核话术或直接转人工，绝不即兴发挥。
>
> **双重输出规范 (Dual Output Standard)**：使用本 Skill 落地时必须**同时**产出：
> 1. **结构化知识库 YAML**：作为引擎输入与存档，价格/承诺/话术逐条可溯源。
> 2. **交互式 HTML Demo**：左侧聊天气泡 + 右侧"透明面板"（命中意图/置信度/知识条目/行动边界决策/是否转人工），供审查与演示。
>
> **输出路径与命名规范 (Output Path & Naming Convention)**：
> - **目录**：业务产物放在以 `[公司/业务名]` 命名的子目录（例如 `私域电商售前客服AI规划/`）。
> - **文件名**：`[公司/业务名]-[内容类型].yaml|html`（例如 `私域电商售前客服-售前问答知识库.yaml`）。
>
> **视觉设计规范 (Visual Design Standard)**：
> - 默认遵循 `ai4pm-skills/design.md`：浅色底 (Light Mode)、容器宽度 **85%**、MiSans 字体优先、品牌色 Starry Blues `#10213E` / Creative Blue `#5DB2E2`。
> - 标准 Header：左侧标题/副标题 + 右侧 `Generated by presales-qa-agent` 与时间戳，底部 `1px` 分割线。
> - Jinja inline style 防坑：动态样式写成 `<div {{ 'style="left:' ~ x ~ 'px;"' }}>`，避免 IDE 误报 CSS 解析错误。

## LLM + 工具工作流

LLM 与工具分工协同，保证可解释、可回归：

```
客户消息 → ① LLM加载知识库 → ② LLM语义意图识别 → ③ LLM选择并调用工具
        → ④ 工具返回确定性数据 → ⑤ LLM基于数据生成话术 → ⑥ 输出（含内部摘要）
```

| 阶段 | 执行者 | 职责 |
|------|--------|------|
| ① 加载知识库 | LLM | 读取 YAML，理解商品/价格/合规/物流数据 |
| ② 语义意图识别 | **LLM** | 理解客户消息语义，判类（version/authenticity/pricing/risk/fulfillment_payment/handoff/identity/greeting）。支持口语化、模糊表达、省略词 |
| ③ 调用工具 | LLM 选择 → 工具执行 | 按意图调用 `answer_engine.py` 对应工具，获取确定性数据 |
| ④ 返回数据 | **工具** | 价格查表/促销计算/合规判定/库存查询（零幻觉） |
| ⑤ 生成话术 | **LLM** | 基于工具返回值，润色成真人客服话术（不改变 `need_human`） |
| ⑥ 输出 | LLM | 对客户话术 + 内部转人工摘要（如有） |

### 工具函数清单（answer_engine.py）

| 工具 | 用途 | 关键参数 |
|------|------|----------|
| `price` | 价格/库存查询 | `--version 日版 --dose 2.5` |
| `promo` | 促销到手价计算 | `--version 孟版 --dose 5.0 --quantity 1` |
| `compliance` | 合规风险判定（白名单/禁忌） | `--msg "能降血糖吗"` |
| `manual_promo` | 人工议价口径检测 | `--msg "优惠10"` |
| `authenticity` | 正品验真凭据 | 无参数 |
| `fulfillment` | 物流支付口径 | 无参数 |
| `product` | 商品版本详情 | `--version 日版` |
| `all_products` | 全部在售商品概览 | 无参数 |

**风险优先级最高**：一旦语义上涉及疾病治疗/禁忌人群/效果承诺，无视其他意图，优先调用 `compliance` 工具。

## 用法

```bash
# 工具调用（LLM 按意图选择工具，获取确定性数据）
python3 scripts/answer_engine.py <kb.yaml> --tool price --version 日版 --dose 2.5
python3 scripts/answer_engine.py <kb.yaml> --tool promo --version 孟版 --dose 5.0
python3 scripts/answer_engine.py <kb.yaml> --tool compliance --msg "能降血糖吗"
python3 scripts/answer_engine.py <kb.yaml> --tool manual_promo --msg "优惠10"
python3 scripts/answer_engine.py <kb.yaml> --tool authenticity
python3 scripts/answer_engine.py <kb.yaml> --tool fulfillment
python3 scripts/answer_engine.py <kb.yaml> --tool product --version 日版
python3 scripts/answer_engine.py <kb.yaml> --tool all_products

# 用测试用例集回归（只验证工具函数确定性数据，意图/话术由LLM测试）
python3 scripts/answer_engine.py <kb.yaml> --replay <test_cases.yaml>

# 由知识库生成交互式 HTML Demo（LLM+工具工作流可视化）
python3 scripts/build_demo.py <kb.yaml> <output.html>
```

## 交互流程 (Workflow)

### IDE内AI运行模式（LLM + 工具协同）

1. **LLM加载**：读取 `agent_system_prompt.md` 理解角色与四条护栏，读取知识库 YAML 获取业务数据。
2. **LLM语义识别**：对客户消息做**语义级意图识别**（非关键词匹配），判断属于哪类意图。支持口语化、模糊表达、省略词、错别字。
3. **LLM调用工具**：按意图调用 `answer_engine.py --tool <tool_name>` 获取确定性数据（价格查表/合规判定/库存）。
4. **LLM话术生成**：基于工具返回的 JSON 数据，润色成自然客服话术。不改变工具返回的 `need_human` 值。

### 离线模式（纯脚本回归）

1. **知识库抽取**：从政策规则清单 / 本体设计 / 真实会话抽取填充 `knowledge_base.schema.yaml` 的各 section；价格数字必须精确抽取，缺失即标 TODO 并转人工兜底，**不臆造数字**。
2. **工具回归**：用测试用例集跑 `--replay`，校验价格类数字一致、治疗/禁忌类 `need_human=true`、缺货档识别正确。意图识别与话术文本由 LLM 在 IDE 内实测。
3. **Demo 生成**：`build_demo.py` 注入知识库 JSON，产出无后端、离线可演示的 LLM+工具工作流可视化 Demo。
4. **交付审查**：结构化 YAML + 交互 HTML 双输出，价格/承诺逐条可溯源。

## 核心原则 (Design Principles)

- **LLM做语义，工具做确定性 (Separation of Concerns)**：LLM负责语义理解、意图识别、话术生成（需要智能的部分）；工具负责价格查表、合规判定、库存查询（需要确定性的部分）。LLM不可绕过工具直接回答价格/合规类问题。
- **确定性 (Determinism)**：价格与优惠只由工具函数算出，同一输入永远得到同一输出，价格零幻觉。
- **可溯源 (Traceability)**：工具返回值能定位到知识库具体条目/规则，话术基于工具数据生成。
- **保守优先 (Fail-safe)**：工具返回 error、意图置信度低、知识库无命中 → 宁可转人工，绝不硬答。
- **无感转接 (Seamless Handoff)**：客户视角下智能客服=真人客服，对客户话术不得出现"转人工/AI/机器人"。

## QA 清单

- [ ] 三条护栏是否在工具函数中硬编码（price查表 / authenticity凭据来源 / compliance白名单）
- [ ] 价格类回复数字是否逐字来自 `--tool price` 返回值，无任何心算
- [ ] 日版 2.5 表价 498 是否正常输出（`--tool price --version 日版 --dose 2.5`）
- [ ] 疾病治疗 / 禁忌人群是否 `--tool compliance` 返回 `need_human=true`
- [ ] 转人工摘要是否为三段式（关注点 + 已答内容 + 未解决问题）
- [ ] Demo 是否 85% 宽度 / Light Mode / MiSans / 标准 Header
- [ ] `--replay` 通过率是否作为工具函数正确性证据留存
- [ ] IDE内AI模式：LLM是否先调`--tool`再做话术润色（不绕过工具直接答价格/合规）
- [ ] LLM生成的话术是否未改变工具返回的 `need_human` 值
- [ ] 对客户话术是否无"转人工/AI/机器人"字样（无感转接）
