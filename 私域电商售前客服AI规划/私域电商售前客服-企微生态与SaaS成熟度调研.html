1企微官方能力与四类接入路径（能力边界事实）

企微已从「连接工具」演进为「AI 底座」，但官方 AI 均为通用能力，无电商售前垂直逻辑。做 1v1 自动回复，官方开放的接入路径只有四条：
P1 · 微信客服（kf 账号）API
客户无需加好友；消息实时回调 + API 发送回复；官方支持全自动对话；可挂抖音落地页入口
✔ 官方唯一支持全自动 1v1 对话的通道

P2 · 聊天工具栏 JSAPI（侧边栏）
H5 页面可获取当前客户 ID，做话术推荐展示；消息发送必须人工点击触发
✘ 只能做 Copilot 辅助，无法全自动——与本项目形态不符
P3 · 会话存档 API（付费）

2AI 能力项成熟度评估（专家质疑的正面回答）

评估口径：成熟 = 多家规模化商用供给、效果经市场验证；部分成熟 = 通用能力可用但行业化/场景化需定制；不成熟 = 无可靠商用供给或技术路线本身不可靠。
能力项成熟度市场证据对本项目的缺口
RAG 知识库问答（通用域）成熟企微智能机器人、阿里云百炼企微助手、各 SCRM AI 问答均规模化商用；FAQ 型问答准确率达商用水平通用 RAG 不解决减肥保健品合规语料问题——语料建设与预审核才是工作量所在
渠道打标 / 自动欢迎语 / 活码分流成熟SCRM 标配十年成熟能力；微伴宣称 AI 标签准确率 95%（厂商口径）直接采购或用企微原生，不构成差异化，勿重复造轮子
敏感词拦截（关键词级）成熟SCRM 会话质检/敏感词拦截标配，多为事后质检关键词级挡不住功效宣称的语义变体（「吃了包瘦」「三天见效」）；语义级合规拦截市场无成熟供给
1v1 全自动对话（通用大模型驱动）部分成熟句子互动等宣称「AI 员工直接上岗」，通用对话流畅度已可用；行业共识：自动运营仍需人工兜底，无品类纵深全自动的瓶颈不在对话能力，而在领域知识 + 合规确定性——恰是 FDE 建库要解决的
促销算账 / 价格计算（大模型直接算）不成熟大模型算术与规则推理不可靠是公认技术边界；无厂商敢让 LLM 独立报价本方案路线：促销规则结构化入 RAG 知识库，检索规则生成确定性结果，大模型仅话术润色——价格决策不由大模型完成
真人话术拟合（语气/风格贴近真人客服）部分成熟基于历史会话微调/少样本模仿技术可行，无开箱即用产品「与真人回答的拟合程度」是本项目验收维度之一，必须基于客户会话存档语料定制
多轮需求澄清（问题链引导）部分成熟通用多轮对话成熟；「正品溯源/版本对比/用法适配」澄清问题链属行业知识工程，无现成供给FDE 建库范围：需求澄清问题链为五大知识库之一
幻觉抑制（不出错、不乱回答）部分成熟RAG + 预审核语料 + 未命中拒答转人工，是当前工程上最可靠的幻觉控制路线；纯生成式回答仍不可控本方案「不设真人在环」的成立前提：RAG 未命中即兜底转人工，而非让模型自由发挥

4成熟度结论：买 / 增强 / 自建

总判定：本项目所需 8 项 AI 能力中——市场已成熟 3 项（直接买/用原生）、部分成熟 4 项（基座可用、行业化需定制）、不成熟 1 项（LLM 直接算价，须用确定性规则路线规避）。

买（Buy）

渠道打标、活码分流、自动欢迎语、关键词敏感词拦截、（如需）侧边栏订单查询 → 采购 SCRM 或用企微原生即可，勿重复造轮子

增强（Enhance）

通用 RAG 问答基座、kf 通道消息回调链路 → 在官方/开源基座上做行业化增强

自建（Build · FDE 核心价值）

减肥保健品合规话术库（预审核）、促销规则库（确定性算账）、需求澄清问题链、真人话术拟合语料工程、RAG 未命中兜底策略

为什么是 FDE：市场供给全部是「工具」形态（SaaS 订阅），效果依赖客户自建知识库与运营——而客户团队 6-20 人、无技术编制，不具备把工具变成「能自动接待的客服」的能力。「FDE 定制交付 × RAG 全自动」组合恰是市场空白象限，也是该业态唯一现实的落地方式。

风险提示

  • 厂商宣称数据（准确率 95%、人效 3 倍）多出自厂商自评，选型必须 POC 实测
  • 员工号 1v1 自动化的通道合规风险须前置确认（kf 通道 vs 员工号自动化的取舍）
  • 白牌保健品若资质不全（无蓝帽子 SKU 宣称减肥功效），AI 放大话术产能的同时会放大合规风险——上线前须完成 SKU 资质审计
  • 企微对营销骚扰风控趋严，自动化触达频率策略需保守设计，避免封号损失私域资产
