# 私域售前 Demo 验收矩阵

## 验收目标

- 对话准确率满足规则可解释要求
- 流程流畅度覆盖首响、问答、转人工、付款承接
- 所有高风险场景都能被硬规则拦住，且不臆造商品、价格或资质能力

## 覆盖清单

- [x] 核心链路：首响、身份、版本/规格、价格/促销、验真、物流支付、付款截图承接（C-001~C-016、C-013A、C-031、C-033、C-036、C-039~C-040）

- [x] 会话状态：人工接管后保持人工服务，解决工单后恢复 AI；固定回归入口每条用例隔离阶段（对应 `tests/api.test.ts`）
- [x] 跨轮：C-040 通过历史上下文先确定日版，再确认保存方式；业务链路限制历史为最近 6 条
- [x] 多模态：图片/语音上传鉴权、魔数校验、签名媒体 URL、图片描述回退与持久化；不虚构为售前文本用例能力（对应 `tests/imageFlow.test.ts`、`tests/media.test.ts`）
- [x] 权限：未登录 401、客服调用客户聊天接口 403、非法角色拒绝、签名令牌篡改失败（对应 `tests/api.test.ts`）
- [x] 异常边界：空消息、非法 mediaUrl、缺货、不存在档位、非在售商品、风险/监管红线、未知问题保守转人工（C-015、C-020~C-030、C-034~C-039）

## 自动化判定维度

| 维度 | 说明 |
| --- | --- |
| 意图识别 | 是否进入正确意图分支 |
| 回复内容 | 是否包含核心口径，不包含违规扩展 |
| 是否转人工 | 高风险场景是否正确触发人工 |
| 行动边界 | 是否命中对应边界决策 |
| 成交阶段推进 | 禁忌人群、风险场景下不推进 dealStage |
| 话术红线 | 不出现未开通的收款方式、疗效承诺或虚构资质 |

## 通过标准

1. 41 条售前用例逐条完成回归，且新增用例与现有商品/规则/工具实现一致
2. 关键场景不出现错价和越权承诺
3. API、人工接管、多模态和权限测试通过
4. 失败用例可定位到具体规则或回复逻辑
