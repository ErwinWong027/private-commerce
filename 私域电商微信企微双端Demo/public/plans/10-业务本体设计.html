客户会话（Session）

进线来源（直播/短视频/投流加粉）
risk_signals string
风险信号（敏感功效词/点名人工/连续追问）

咨询意图（Intent）

sub_intent string
子意图（payment_methods / payment_completed / delivery_time / shipping_origin 等），决定工具参数与成交阶段推进
sentence_type enum
question / non_question 句式类型（非疑问句不触发转人工）
has_question_signal boolean
确定性兜底信号，命中疑问信号时把 non_question 只升不降地升格为 question
confidence number
意图识别置信度
risk_dimensions string
风险维度（已知/缺失维度，仅 compliance 工具命中时计算）
matched_keywords string
命中的分类词典关键词
⚠️ 概念边界
≠ 意图识别成功 ≠ 知识库有答案，命中不足必须保守答复
≠ 价格类意图 ≠ 可自由作答，必须走规则表输出
≠ 风险类意图一旦命中，优先级高于其他所有意图
≠ sentence_type=non_question 时即便命中 handoff 词也不转人工，避免闲聊误转

商品版本（Version）

包装形式（一盒两支/一盒一支）
product_form string
剂型（原研自动笔/仿制针剂）
usage_desc string
使用口径（一盒一针，一针一次，管一个星期）

≠ 珠峰=孟版杰西卡低配版，不是独立第四版本
≠ 日版只能整盒购买，不能拆开卖
≠ 替C = 替尔 = 替尔泊肽，是同一成分的不同叫法
≠ 国版穆峰达需去医院开，本店不售，不能报价

规格价格（SKU）

版本×剂量档的权威价格表（孟版 6 档 / 日版 6 档含 1 档缺货 / 珠峰 4 档，共 16 条）

2.5 / 5.0 / 7.5 / 10 / 12.5 / 15 剂量档位
list_price number
表价（价格表图口径）
stock_status enum
in_stock / out_of_stock 库存状态（日版 15 暂缺货）
⚠️ 概念边界
≠ 表价为唯一权威报价，价格已统一不存在会话浮动口径
≠ 珠峰仅 2.5/5.0/7.5/10 四档，无 12.5/15 档
≠ 缺货档位不能报价成交，只能说明缺货
参考对象
促销规则（Promo）

condition string
触发条件（版本/件数/活动场次）
result string
优惠结果（减免金额）
validity enum
active / expired / manual_only 规则状态
⚠️ 概念边界
≠ 人工议价口径（优惠10/1200-80）≠ 可自动执行的规则
≠ 活动口径有场次有效期，过期规则不能继续报
≠ 赠品/优惠条件必须明确表述，不能模糊表达
参考对象
正品凭据（Proof）

支撑正品信任应答的凭据集：验真流程（扫码/官网/三码合一）、包装图、假货退款承诺

proof_type enum
验真流程卡 / 包装图 / 版本对比卡 / 退款承诺口径 凭据类型
is_real_collected boolean
是否真实采集（补充样例须显式标注）
display_content string
可公开展示的凭据内容
⚠️ 概念边界
≠ 正品凭据只能来自知识库，不允许模型自由编造
≠ 禁止伪造批准文号、注册证书编号、质检结论、蓝帽子编号
≠ 样例凭据卡 ≠ 真实业务承诺，演示时必须标注
参考对象
合规话术白名单（Whitelist）

预审核的风险问答话术库：效果/治疗/副作用禁忌等敏感问题只能走白名单语料

intent enum
效果承诺 / 疾病治疗 / 副作用与禁忌 覆盖的敏感意图
trigger_words string
触发词（瘦多少/治疗/孕妇/甲状腺等）
response_mode enum
safe_reply / transfer 应答模式（保守回复/直接转人工）
reply string
预审核的白名单回复文本
⚠️ 概念边界
≠ 白名单外的风险问题一律保守回复或转人工，不允许即兴发挥
≠ 点对点交流受众特定 ≠ 可放松合规标准，仍按广告高标准执行
≠ 禁忌人群说明只能按固定口径回复，不做个体医疗建议
事件对象
转人工工单（Handoff）

AI 转人工的事件记录，含触发原因与供人工接手的上下文摘要

trigger_type enum
敏感功效 / 低置信度 / 客户点名人工 / 付款承接 / 口径冲突 转人工触发原因
summary string
上下文摘要（客户关注点+已答内容+未解决问题）
status enum
pending / taken_over / resolved 人工接管状态
⚠️ 概念边界
≠ 转人工 ≠ AI 回答失败，是设计内的兜底路径
≠ 工单创建 ≠ 人工已接管，未接管前客户仍在等待
≠ 摘要缺失的转接会让人工重新问一遍，等于二次伤害体验
事件对象
下单承接（Order Intake）

客户确认购买后的承接记录：付款截图 → 收货信息 → 客服复述核对 → 晚点发单号

payment_method enum
微信 / 支付宝 支付方式（企微内转账与红包均未开通，仅微信/支付宝两种可用）
payment_screenshot boolean
是否已收到付款截图
address_confirmed boolean
订单要素是否已人工复述核对
shipping_desc string
发货口径（深圳发/48h 内发出/冷链到付约 20 元，非固定，以后台运单数据为准）
⚠️ 概念边界
≠ 收到付款截图 ≠ 订单完成，必须人工复述订单要素核对
≠ 发货时效口径（揽收后 1-3 天）≠ 承诺具体到货日期
≠ AI 只做支付/发货口径说明，不能自动确认收款成功
参考对象
试点守护指标（Metric）

小流量试点看板：首响时长、自动接待率、转人工率、错价次数、首单转化率。当前 Demo 的 metrics 表只有 total_messages / ai_replies / handoffs 三个累计计数，其余为演示口径

total_messages number
累计消息数（metrics 表实存键）
ai_replies number
累计 AI 回复数（metrics 表实存键）
handoffs number
累计转人工工单数（metrics 表实存键）
conversion_rate number
首单转化率（演示口径：已核对订单数 ÷ 消息数；正式口径应为成交会话数 ÷ 会话数，健康区间 9%~10%；业务级 NSM 为 LTV）
handoff_rate number
转人工率（演示口径：handoffs ÷ total_messages，分子分母量纲不同；正式口径应为工单数 ÷ 会话数）
auto_serve_rate number
RAG 自动接待率（目标 ≥80%，规划中，当前未落库）
wrong_price_count number
错价事件次数（硬红线指标，规划中，当前未落库）
observation_weeks number
连续观察周数（回滚判定窗口）
⚠️ 概念边界
≠ 演示口径的派生指标分子分母量纲不同，不可作为业务结论
≠ 单日转化波动 ≠ 试点失败，回滚判定看连续两周口径
≠ 自动接待率高 ≠ 试点成功，转化率不掉才是守护底线
≠ 错价一次即需复盘，不能等汇总周期
核心对象
成交进度（Deal State）

单会话的成交阶段与模拟运单号，是话术红线校验的唯一事实依据（deal_states 表）

stage enum
consulting / awaiting_payment / awaiting_review / awaiting_shipment / awaiting_pickup / picked_up / in_transit 成交阶段（与 DEAL_STAGE_ORDER 顺序一致，只前进不后退）
tracking_no string
模拟运单号（由人工 generate_tracking 动作生成）
updated_at datetime
最近一次阶段推进时间
⚠️ 概念边界
≠ AI 只能把阶段推进到 awaiting_review，其后每一步必须由人工动作触发
≠ 阶段只前进不后退，跨阶段推进一律拒绝
≠ 阶段是话术事实性措辞的唯一依据，模型不得自行宣布未到达的阶段
核心对象
人工客服（Agent Operator）

人工客服「小禾」（U-AGENT-001），是所有事实性确认动作的唯一执行者（users 表 role=agent）

operator_id string
客服标识（Demo 固定为 U-AGENT-001）
display_name string
展示名（小禾）
manual_actions enum
confirm_review / generate_tracking / simulate_pickup / simulate_transit 可执行的四个人工推进动作
⚠️ 概念边界
≠ 收款成功、已发货、已揽收等既成事实只能由人工确认，AI 无权宣布
≠ 多模态识别结果须经人工确认后才构成业务事实
≠ 人工接管 ≠ AI 失败，是设计内的固定环节

多模态素材（Media Asset，规划中）

客户发送的语音/图片素材及其识别结果，只作为人工判断的输入，不构成成交事实（规划中，待建 media_assets 表）

media_type enum
image / audio 素材类型
source string
来源（企微会话消息/人工上传）
extracted_text string
识别文本（OCR / ASR 结果）
confidence number
识别置信度
confirmed_by_operator boolean
是否已由人工客服确认
⚠️ 概念边界
≠ 识别结果 ≠ 业务事实，付款截图金额/时间须人工确认后才生效
≠ 识别文本只进不出：落在人工可见区，不直接回给客户
≠ 多模态不推进 deal_state.stage

情境 1
客户进线首响承接
客户从直播/投流进入企微发出第一句咨询（你好/在吗/7.5 什么价），首轮信任窗口只有秒级
📋 Required Evidence
企微 kf 消息回调
确认收到客户首条消息及其文本内容
欢迎语模板库
统一欢迎语与首轮引导语模板已配置且为当前版本
✅ Valid Actions
秒级发送统一欢迎语完成首轮承接
引导客户确认咨询主题（版本/正品/价格等）
识别首条消息中已包含的意图并直接路由
❌ Invalid Actions
等待人工上线再回复客户首条消息
原因：夜间/高峰冷场直接导致第一轮信任未建立即流失
在欢迎语中自由生成优惠或效果承诺
原因：欢迎语必须走预置模板，即兴承诺会踩价格与合规红线
⚠️ Exception Triggers
当：客户首条消息即命中敏感功效词或点名人工
→ 跳过常规分流，直接输出保守话术并创建转人工工单
情境 2
客户质疑正品或要求验真
客户问「是不是正品/能验吗/日版孟版什么区别」，是成交前最高频的信任决策点
📋 Required Evidence
正品溯源与商品库
验真流程卡、包装图、版本对比卡在库且为真实采集内容
退款承诺口径
「验出假货可退」为真实会话中确认过的标准口径
✅ Valid Actions
检索并输出验真流程（扫码/官网/三码合一）
输出版本差异说明（不展示包装图，仅输出验真路径）
按标准口径说明假货退款承诺
凭据不足时保守答复并转人工
❌ Invalid Actions
编造批准文号、注册证书、质检结论、蓝帽子编号等监管凭据
原因：伪造监管信息是合规硬红线，Demo 也不例外
用「绝对正品/官方唯一授权」等绝对化背书作答
原因：绝对化表述违反广告法，凭据只能展示可验证路径
⚠️ Exception Triggers
当：客户已收货并声称扫码验真失败
→ 立即按退款承诺口径回应并转人工处理售后
情境 3
客户询价议价或问多件优惠

版本×剂量档的表价与库存状态（日版 15 缺货）
促销规则库
当前生效的活动规则与适用条件（618 减 20 等）
✅ Valid Actions

# 业务本体：私域电商售前AI助手-Agent本体设计
领域：私域电商售前
Agent 角色：企微 AI 售前助手（RAG 1v1 自动回复）
场景：客户从抖音直播/投流进入企微 1v1 后，AI 售前助手完成秒级首响、意图分流、正品信任应答、确定性算账，遇敏感功效/低置信/点名人工即附摘要转人工，并以小流量试点看板守护转化率的端到端售前场景

## 1. 核心业务对象与概念边界
### 客户会话（Session） [核心对象]
- 定义：客户在企微发起的 1v1 售前会话，是所有意图识别、应答与转人工动作的载体
- 属性定义：
  * status (enum)（可选值：ai_serving / human_serving / closed） - 会话承接状态（与双端 Demo 的 SessionStatus 一致）
  * first_response_at (datetime) - 首响时间（秒级首响考核口径）
  * source_channel (string) - 进线来源（直播/短视频/投流加粉）
  * risk_signals (string) - 风险信号（敏感功效词/点名人工/连续追问）
- 关键概念边界（不可混淆）：
  ⚠️ 客户进线 ≠ 已完成首响，冷场即流失第一轮成交窗口
  ⚠️ AI 承接中 ≠ 全自动闭环，转人工是正常路径不是失败
  ⚠️ 会话来源打标（C3）不在本期范围，不能假设来源已知
### 咨询意图（Intent） [事件对象]
- 定义：对客户每轮问题的分类结果，决定路由到哪类应答（版本/正品/价格/风险/发货付款/转人工）
- 属性定义：
  * category (enum)（可选值：greeting / identity / handoff / risk / fulfillment_payment / pricing / authenticity / version / unknown） - 主意图类别（对应 IntentPlan.intent）
  * sub_intent (string) - 子意图（payment_methods / payment_completed / delivery_time / shipping_origin 等），决定工具参数与成交阶段推进
  * sentence_type (enum)（可选值：question / non_question） - 句式类型（非疑问句不触发转人工）
  * has_question_signal (boolean) - 确定性兜底信号，命中疑问信号时把 non_question 只升不降地升格为 question
  * confidence (number) - 意图识别置信度
  * risk_dimensions (string) - 风险维度（已知/缺失维度，仅 compliance 工具命中时计算）
  * matched_keywords (string) - 命中的分类词典关键词
- 关键概念边界（不可混淆）：
  ⚠️ 意图识别成功 ≠ 知识库有答案，命中不足必须保守答复
  ⚠️ 价格类意图 ≠ 可自由作答，必须走规则表输出
  ⚠️ 风险类意图一旦命中，优先级高于其他所有意图
  ⚠️ sentence_type=non_question 时即便命中 handoff 词也不转人工，避免闲聊误转
### 商品版本（Version） [核心对象]
- 定义：在售三版本：日版礼来（一盒两支/自动笔）、孟版杰西卡（一盒一支/针剂）、珠峰（孟版低配版）
- 属性定义：
  * version_name (enum)（可选值：日版礼来 / 孟版杰西卡 / 珠峰） - 版本名称
  * package_desc (string) - 包装形式（一盒两支/一盒一支）
  * product_form (string) - 剂型（原研自动笔/仿制针剂）
  * usage_desc (string) - 使用口径（一盒一针，一针一次，管一个星期）
  * storage_desc (string) - 保存口径（未开封 2-8°C 冷藏；已开封 <30°C 存 21 天）
- 关键概念边界（不可混淆）：
  ⚠️ 珠峰=孟版杰西卡低配版，不是独立第四版本
  ⚠️ 日版只能整盒购买，不能拆开卖
  ⚠️ 替C = 替尔 = 替尔泊肽，是同一成分的不同叫法
  ⚠️ 国版穆峰达需去医院开，本店不售，不能报价
### 规格价格（SKU） [核心对象]
- 定义：版本×剂量档的权威价格表（孟版 6 档 / 日版 6 档含 1 档缺货 / 珠峰 4 档，共 16 条）
- 属性定义：
  * dose (enum)（可选值：2.5 / 5.0 / 7.5 / 10 / 12.5 / 15） - 剂量档位
  * list_price (number) - 表价（价格表图口径）
  * stock_status (enum)（可选值：in_stock / out_of_stock） - 库存状态（日版 15 暂缺货）
- 关键概念边界（不可混淆）：
  ⚠️ 表价为唯一权威报价，价格已统一不存在会话浮动口径
  ⚠️ 珠峰仅 2.5/5.0/7.5/10 四档，无 12.5/15 档
  ⚠️ 缺货档位不能报价成交，只能说明缺货
### 促销规则（Promo） [参考对象]
- 定义：结构化优惠规则：618 孟版单支减 20、日版一盒减 20；到手价只能由规则表算出
- 属性定义：
  * condition (string) - 触发条件（版本/件数/活动场次）
  * result (string) - 优惠结果（减免金额）
  * validity (enum)（可选值：active / expired / manual_only） - 规则状态
- 关键概念边界（不可混淆）：
  ⚠️ 人工议价口径（优惠10/1200-80）≠ 可自动执行的规则
  ⚠️ 活动口径有场次有效期，过期规则不能继续报
  ⚠️ 赠品/优惠条件必须明确表述，不能模糊表达
### 正品凭据（Proof） [参考对象]
- 定义：支撑正品信任应答的凭据集：验真流程（扫码/官网/三码合一）、包装图、假货退款承诺
- 属性定义：
  * proof_type (enum)（可选值：验真流程卡 / 包装图 / 版本对比卡 / 退款承诺口径） - 凭据类型
  * is_real_collected (boolean) - 是否真实采集（补充样例须显式标注）
  * display_content (string) - 可公开展示的凭据内容
- 关键概念边界（不可混淆）：
  ⚠️ 正品凭据只能来自知识库，不允许模型自由编造
  ⚠️ 禁止伪造批准文号、注册证书编号、质检结论、蓝帽子编号
  ⚠️ 样例凭据卡 ≠ 真实业务承诺，演示时必须标注
### 合规话术白名单（Whitelist） [参考对象]
- 定义：预审核的风险问答话术库：效果/治疗/副作用禁忌等敏感问题只能走白名单语料
- 属性定义：
  * intent (enum)（可选值：效果承诺 / 疾病治疗 / 副作用与禁忌） - 覆盖的敏感意图
  * trigger_words (string) - 触发词（瘦多少/治疗/孕妇/甲状腺等）
  * response_mode (enum)（可选值：safe_reply / transfer） - 应答模式（保守回复/直接转人工）
  * reply (string) - 预审核的白名单回复文本
- 关键概念边界（不可混淆）：
  ⚠️ 白名单外的风险问题一律保守回复或转人工，不允许即兴发挥
  ⚠️ 点对点交流受众特定 ≠ 可放松合规标准，仍按广告高标准执行
  ⚠️ 禁忌人群说明只能按固定口径回复，不做个体医疗建议
### 转人工工单（Handoff） [事件对象]
- 定义：AI 转人工的事件记录，含触发原因与供人工接手的上下文摘要
- 属性定义：
  * trigger_type (enum)（可选值：敏感功效 / 低置信度 / 客户点名人工 / 付款承接 / 口径冲突） - 转人工触发原因
  * summary (string) - 上下文摘要（客户关注点+已答内容+未解决问题）
  * status (enum)（可选值：pending / taken_over / resolved） - 人工接管状态
- 关键概念边界（不可混淆）：
  ⚠️ 转人工 ≠ AI 回答失败，是设计内的兜底路径
  ⚠️ 工单创建 ≠ 人工已接管，未接管前客户仍在等待
  ⚠️ 摘要缺失的转接会让人工重新问一遍，等于二次伤害体验
### 下单承接（Order Intake） [事件对象]
- 定义：客户确认购买后的承接记录：付款截图 → 收货信息 → 客服复述核对 → 晚点发单号
- 属性定义：
  * payment_method (enum)（可选值：微信 / 支付宝） - 支付方式（企微内转账与红包均未开通，仅微信/支付宝两种可用）
  * payment_screenshot (boolean) - 是否已收到付款截图
  * address_confirmed (boolean) - 订单要素是否已人工复述核对
  * shipping_desc (string) - 发货口径（深圳发/48h 内发出/冷链到付约 20 元，非固定，以后台运单数据为准）
- 关键概念边界（不可混淆）：
  ⚠️ 收到付款截图 ≠ 订单完成，必须人工复述订单要素核对
  ⚠️ 发货时效口径（揽收后 1-3 天）≠ 承诺具体到货日期
  ⚠️ AI 只做支付/发货口径说明，不能自动确认收款成功
### 试点守护指标（Metric） [参考对象]
- 定义：小流量试点看板：首响时长、自动接待率、转人工率、错价次数、首单转化率。当前 Demo 的 metrics 表只有 total_messages / ai_replies / handoffs 三个累计计数，其余为演示口径
- 属性定义：
  * total_messages (number) - 累计消息数（metrics 表实存键）
  * ai_replies (number) - 累计 AI 回复数（metrics 表实存键）
  * handoffs (number) - 累计转人工工单数（metrics 表实存键）
  * conversion_rate (number) - 首单转化率（演示口径：已核对订单数 ÷ 消息数；正式口径应为成交会话数 ÷ 会话数，健康区间 9%~10%；业务级 NSM 为 LTV）
  * handoff_rate (number) - 转人工率（演示口径：handoffs ÷ total_messages，分子分母量纲不同；正式口径应为工单数 ÷ 会话数）
  * auto_serve_rate (number) - RAG 自动接待率（目标 ≥80%，规划中，当前未落库）
  * wrong_price_count (number) - 错价事件次数（硬红线指标，规划中，当前未落库）
  * observation_weeks (number) - 连续观察周数（回滚判定窗口）
- 关键概念边界（不可混淆）：
  ⚠️ 演示口径的派生指标分子分母量纲不同，不可作为业务结论
  ⚠️ 单日转化波动 ≠ 试点失败，回滚判定看连续两周口径
  ⚠️ 自动接待率高 ≠ 试点成功，转化率不掉才是守护底线
  ⚠️ 错价一次即需复盘，不能等汇总周期
### 成交进度（Deal State） [核心对象]
- 定义：单会话的成交阶段与模拟运单号，是话术红线校验的唯一事实依据（deal_states 表）
- 属性定义：
  * stage (enum)（可选值：consulting / awaiting_payment / awaiting_review / awaiting_shipment / awaiting_pickup / picked_up / in_transit） - 成交阶段（与 DEAL_STAGE_ORDER 顺序一致，只前进不后退）
  * tracking_no (string) - 模拟运单号（由人工 generate_tracking 动作生成）
  * updated_at (datetime) - 最近一次阶段推进时间
- 关键概念边界（不可混淆）：
  ⚠️ AI 只能把阶段推进到 awaiting_review，其后每一步必须由人工动作触发
  ⚠️ 阶段只前进不后退，跨阶段推进一律拒绝
  ⚠️ 阶段是话术事实性措辞的唯一依据，模型不得自行宣布未到达的阶段
### 人工客服（Agent Operator） [核心对象]
- 定义：人工客服「小禾」（U-AGENT-001），是所有事实性确认动作的唯一执行者（users 表 role=agent）
- 属性定义：
  * operator_id (string) - 客服标识（Demo 固定为 U-AGENT-001）
  * display_name (string) - 展示名（小禾）
  * manual_actions (enum)（可选值：confirm_review / generate_tracking / simulate_pickup / simulate_transit） - 可执行的四个人工推进动作
- 关键概念边界（不可混淆）：
  ⚠️ 收款成功、已发货、已揽收等既成事实只能由人工确认，AI 无权宣布
  ⚠️ 多模态识别结果须经人工确认后才构成业务事实
  ⚠️ 人工接管 ≠ AI 失败，是设计内的固定环节
### 多模态素材（Media Asset，规划中） [事件对象]
- 定义：客户发送的语音/图片素材及其识别结果，只作为人工判断的输入，不构成成交事实（规划中，待建 media_assets 表）
- 属性定义：
  * media_type (enum)（可选值：image / audio） - 素材类型
  * source (string) - 来源（企微会话消息/人工上传）
  * extracted_text (string) - 识别文本（OCR / ASR 结果）
  * confidence (number) - 识别置信度
  * confirmed_by_operator (boolean) - 是否已由人工客服确认
- 关键概念边界（不可混淆）：
  ⚠️ 识别结果 ≠ 业务事实，付款截图金额/时间须人工确认后才生效
  ⚠️ 识别文本只进不出：落在人工可见区，不直接回给客户
  ⚠️ 多模态不推进 deal_state.stage

## 2. 对象关系依赖（Relationships）
- 【客户会话（Session）】 --(触发, 基数 1:N)--> 【咨询意图（Intent）】
  说明：一次会话中客户会连续抛出多轮不同类别的问题
- 【咨询意图（Intent）】 --(涉及, 基数 N:N)--> 【商品版本（Version）】
  说明：版本/正品/价格类意图都会落到具体商品版本上
- 【商品版本（Version）】 --(包含, 基数 1:N)--> 【规格价格（SKU）】
  说明：一个版本包含多个剂量档位的规格价格
- 【促销规则（Promo）】 --(约束, 基数 N:N)--> 【规格价格（SKU）】
  说明：促销规则按版本/件数作用于规格表价，算出到手价
- 【正品凭据（Proof）】 --(证明, 基数 N:N)--> 【商品版本（Version）】
  说明：验真流程、包装图等凭据支撑各版本的正品信任应答
- 【合规话术白名单（Whitelist）】 --(约束, 基数 N:N)--> 【咨询意图（Intent）】
  说明：风险类意图必须匹配白名单话术才能作答
- 【咨询意图（Intent）】 --(触发, 基数 N:1)--> 【转人工工单（Handoff）】
  说明：敏感功效/低置信/点名人工的意图触发转人工工单
- 【客户会话（Session）】 --(产生, 基数 1:N)--> 【下单承接（Order Intake）】
  说明：会话内客户确认购买后产生下单承接记录
- 【转人工工单（Handoff）】 --(执行, 基数 1:1)--> 【下单承接（Order Intake）】
  说明：付款承接类工单由人工接管完成订单要素核对
- 【客户会话（Session）】 --(汇入, 基数 N:1)--> 【试点守护指标（Metric）】
  说明：所有试点会话的首响/转接/成交数据汇入守护看板
- 【客户会话（Session）】 --(持有, 基数 1:1)--> 【成交进度（Deal State）】
  说明：每个会话持有一份成交进度记录，阶段决定话术可用的事实性措辞
- 【人工客服（Agent Operator）】 --(推进, 基数 1:N)--> 【成交进度（Deal State）】
  说明：awaiting_review 之后的每一次阶段推进都必须由人工客服执行
- 【多模态素材（Media Asset，规划中）】 --(佐证, 基数 N:1)--> 【下单承接（Order Intake）】
  说明：付款截图等素材的识别结果作为下单承接的输入，须经人工确认才生效（规划中）

## 3. 行动边界限制（情境 - 证据 - 合法/禁止动作）
### 情境：客户进线首响承接
描述：客户从直播/投流进入企微发出第一句咨询（你好/在吗/7.5 什么价），首轮信任窗口只有秒级
必须核实的证据：
  - [企微 kf 消息回调] 确认收到客户首条消息及其文本内容
  - [欢迎语模板库] 统一欢迎语与首轮引导语模板已配置且为当前版本
✅ 合法动作（允许执行）：
  - 秒级发送统一欢迎语完成首轮承接
  - 引导客户确认咨询主题（版本/正品/价格等）
  - 识别首条消息中已包含的意图并直接路由
❌ 禁止动作（严禁执行，防范错误假设）：
  - 等待人工上线再回复客户首条消息 （禁止原因：夜间/高峰冷场直接导致第一轮信任未建立即流失）
  - 在欢迎语中自由生成优惠或效果承诺 （禁止原因：欢迎语必须走预置模板，即兴承诺会踩价格与合规红线）
⚠️ 异常触发规则：
  - 当满足条件【客户首条消息即命中敏感功效词或点名人工】 → 必须执行：跳过常规分流，直接输出保守话术并创建转人工工单
### 情境：客户质疑正品或要求验真
描述：客户问「是不是正品/能验吗/日版孟版什么区别」，是成交前最高频的信任决策点
必须核实的证据：
  - [正品溯源与商品库] 验真流程卡、包装图、版本对比卡在库且为真实采集内容
  - [退款承诺口径] 「验出假货可退」为真实会话中确认过的标准口径
✅ 合法动作（允许执行）：
  - 检索并输出验真流程（扫码/官网/三码合一）
  - 输出版本差异说明（不展示包装图，仅输出验真路径）
  - 按标准口径说明假货退款承诺
  - 凭据不足时保守答复并转人工
❌ 禁止动作（严禁执行，防范错误假设）：
  - 编造批准文号、注册证书、质检结论、蓝帽子编号等监管凭据 （禁止原因：伪造监管信息是合规硬红线，Demo 也不例外）
  - 用「绝对正品/官方唯一授权」等绝对化背书作答 （禁止原因：绝对化表述违反广告法，凭据只能展示可验证路径）
⚠️ 异常触发规则：
  - 当满足条件【客户已收货并声称扫码验真失败】 → 必须执行：立即按退款承诺口径回应并转人工处理售后
### 情境：客户询价议价或问多件优惠
描述：客户问「一支多少/买两支优惠吗/运费怎么算」，错价是硬红线且直接产生客诉
必须核实的证据：
  - [规格价格表（16 条全规格）] 版本×剂量档的表价与库存状态（日版 15 缺货）
  - [促销规则库] 当前生效的活动规则与适用条件（618 减 20 等）
✅ 合法动作（允许执行）：
  - 调用规则表计算到手价并附活动说明
  - 说明冷链到付运费约 20 元（非固定，以后台运单数据为准）
  - 对缺货档位如实说明缺货，不引导成交
❌ 禁止动作（严禁执行，防范错误假设）：
  - 让大模型脱离规则表自行心算或估算价格 （禁止原因：价格禁止大模型独立决策，防幻觉错价）
  - 复用会话中的人工议价口径自动给客户减价 （禁止原因：人工口径（优惠10/1200-80）未结构化，自动执行会口径失控）
⚠️ 异常触发规则：
  - 当满足条件【客户提出规则库外的议价或组合优惠诉求】 → 必须执行：不承诺任何减免，附摘要转人工由客服决定
### 情境：客户问效果副作用禁忌或治疗
描述：客户问「能瘦多少/能治病吗/孕妇能用吗」，是最容易踩广告法红线的环节
必须核实的证据：
  - [合规话术白名单库] 触发词命中情况与对应 response_mode（safe_reply/transfer）
  - [禁忌人群固定口径] 甲状腺病史/胰岛素用药/孕产期等禁忌说明为预审核版本
✅ 合法动作（允许执行）：
  - 按白名单输出预审核的保守话术
  - 按固定口径说明常见反应与禁忌慎用人群
  - 白名单未覆盖时输出保守答复并附摘要转人工
❌ 禁止动作（严禁执行，防范错误假设）：
  - 对效果作出断言或保证（保证瘦/多久见效） （禁止原因：广告法禁止效果承诺，保健品语境零容忍）
  - 回应疾病预防治疗类问题（降血糖/替代药物） （禁止原因：涉及治疗功能是绝对红线，只能转人工）
  - 对禁忌人群给出个体化使用建议 （禁止原因：超出白名单的医疗判断必须由人工承接）
⚠️ 异常触发规则：
  - 当满足条件【命中疾病治疗类触发词（治疗/降血糖/治好）】 → 必须执行：response_mode=transfer，立即保守回复并转人工
  - 当满足条件【客户自述属禁忌人群仍坚持购买】 → 必须执行：不推进成交流程，附完整摘要转人工处理
### 情境：客户确认购买进入付款发货
描述：客户问「怎么付款/从哪发/多久到」并发出付款截图，进入 AI 说明+人工承接的交界点
必须核实的证据：
  - [支付与发货口径库] 支付方式（微信/支付宝）、48h 发出、揽收后 1-3 天口径
  - [会话中的付款截图与收货信息] 客户是否已发付款截图及姓名电话地址
✅ 合法动作（允许执行）：
  - 说明支付方式与冷链到付运费口径
  - 按口径说明发货时效，不承诺具体到货日
  - 收到付款截图后立即创建付款承接工单转人工
  - 提示客户等待客服复述订单要素核对
❌ 禁止动作（严禁执行，防范错误假设）：
  - 自动向客户确认收款成功或订单已生效 （禁止原因：AI 无支付系统对账能力，误确认会造成资损纠纷）
  - 跳过人工复述核对直接承诺发货 （禁止原因：订单要素核对是真实流程的固定动作，不可省略）
⚠️ 异常触发规则：
  - 当满足条件【客户已付款但超时无人工接管工单】 → 必须执行：升级提醒值班客服，并向客户发送安抚话术
### 情境：话术中的既成事实措辞与成交阶段校验
描述：客户问「发了吗/什么时候到/收到钱了吗」，模型极易顺着客户预期宣布尚未发生的事实（防跳步 T02）
必须核实的证据：
  - [deal_states 表] 当前会话的 deal_state.stage 取值
  - [红线规则表 REDLINES] 话术是否命中 payment_confirmed / shipment_declared / pickup_declared 三类措辞及其 allowedFrom 阶段
✅ 合法动作（允许执行）：
  - 发货与时效类提问一律按当前真实阶段改写话术（buildStageAwareShippingReply）
  - 命中红线时用阶段安全话术整段覆盖（buildStageSafeFallback），只承接不宣布
  - 客户侧确定性推进只在 fulfillment 工具命中时执行，上限锁在 awaiting_review
❌ 禁止动作（严禁执行，防范错误假设）：
  - 在 awaiting_shipment 之前说「收款成功/已收到款」 （禁止原因：收款确认只能由人工核对后给出，提前宣布造成资损与信任纠纷）
  - 在 awaiting_pickup 之前说「已发货/单号已出」 （禁止原因：运单尚未生成，宣布发货即为虚假承诺）
  - 在 picked_up 之前说「已揽收/快递已取件」 （禁止原因：揽收是物流侧既成事实，未发生不得宣布）
  - 让模型自由表达发货时效 （禁止原因：时效措辞必须由阶段感知模板生成，自由表达会跳步）
⚠️ 异常触发规则：
  - 当满足条件【话术命中红线且当前阶段不满足 allowedFrom】 → 必须执行：整段替换为阶段安全话术，并写入 trace-stage-guard 留痕
### 情境：客户发送语音或图片（规划中）
描述：客户直接发语音提问或发付款截图/商品图，需要先归一化为文本才能进入既有链路
必须核实的证据：
  - [多模态识别服务] 识别文本、置信度与素材类型已产出
  - [agent_operator 确认记录] 付款截图的金额/时间提取结果是否已由人工确认
✅ 合法动作（允许执行）：
  - 把语音/图片归一化为文本与结构化字段后进入 s_incoming
  - 把识别文本呈现在人工可见区，供人工判断
  - 提示客户「已收到，正在为您核对」
❌ 禁止动作（严禁执行，防范错误假设）：
  - 把识别结果当作成交事实并推进 deal_state.stage （禁止原因：识别有误判概率，只进不出是硬约束）
  - 把原始识别文本直接回给客户 （禁止原因：识别噪声外露会损害专业感，且可能复述错误金额）
⚠️ 异常触发规则：
  - 当满足条件【识别置信度低或识别失败】 → 必须执行：不做任何事实推断，提示人工查看原始素材

## 4. 状态流转与全局护栏（Workstreams & States）
### 执行流（Workstream）：售前应答流
描述：从客户进线到 AI 完成应答或转人工的核心执行流，覆盖多模态归一化、首响、分流、知识应答、阶段校验五段（对应 presalesGraph.ts 的 START → orchestrate →（humanBranch | stageGate）→ END）
状态节点及迁移路径：
  - 状态：素材归一化（规划中） (s_media_normalize)
    状态定义：客户发来语音/图片时先做识别与结构化，产出识别文本供人工可见；不产出成交事实、不推进阶段
    可用的状态转移路径：
      * --[识别完成并归一化为文本与结构化字段] (核实证据: media_asset.extracted_text 已产出（或识别失败已留痕）)--> 到达状态 s_incoming (性质: 正常迁移)
  - 状态：进线待首响 (s_incoming)
    状态定义：kf 回调收到客户首条消息，欢迎语尚未发出，首轮信任窗口计时中
    可用的状态转移路径：
      * --[发送欢迎语并完成首轮承接] (核实证据: 首响消息已发出，first_response_at 已记录且在秒级)--> 到达状态 s_intent_routing (性质: 正常迁移)
      * --[识别首条消息即命中风险信号] (核实证据: 敏感功效词或「转人工」关键词命中记录)--> 到达状态 s_handoff (性质: 异常分支)
  - 状态：意图分流中 (s_intent_routing)
    状态定义：对客户问题做分类，决定走版本/正品/价格/风险哪条应答路径；叠加 hasQuestionSignal 等确定性兜底
    可用的状态转移路径：
      * --[意图识别成功并路由到对应知识库] (核实证据: intent.category 已判定且 confidence 达阈值)--> 到达状态 s_kb_answering (性质: 正常迁移)
      * --[低置信度或客户点名人工] (核实证据: confidence 低于阈值，或命中转人工触发词且 sentence_type=question)--> 到达状态 s_handoff (性质: 异常分支)
  - 状态：知识库应答中 (s_kb_answering)
    状态定义：按意图检索正品凭据/价格规则/白名单话术，大模型只做话术组织
    可用的状态转移路径：
      * --[输出知识库支撑的候选话术] (核实证据: 应答内容全部可溯源到凭据库/规则表/白名单)--> 到达状态 s_stage_gate (性质: 正常迁移)
      * --[知识库命中不足输出保守答复] (核实证据: 检索无命中或命中低于置信阈值的记录)--> 到达状态 s_handoff (性质: 异常分支)
  - 状态：阶段校验中 (s_stage_gate)
    状态定义：按 deal_state.stage 校验话术中的既成事实措辞，命中红线整段覆盖；同时计算客户侧确定性阶段推进
    可用的状态转移路径：
      * --[校验通过或已按阶段改写后放行] (核实证据: 无红线命中，或已写入 trace-stage-guard 留痕)--> 到达状态 s_answered (性质: 正常迁移)
  - 状态：应答完成 (s_answered)
    状态定义：本轮问题已答复，会话回到等待客户下一轮输入或进入下单承接
    可用的状态转移路径：
      * --[客户发起下一轮问题] (核实证据: kf 回调收到客户新消息)--> 到达状态 s_intent_routing (性质: 正常迁移)
  - 状态：已转人工 (s_handoff)
    状态定义：转人工工单已创建并附上下文摘要，等待人工接管，AI 停止实质作答；该分支不改写话术，但阶段推进仍走同一套确定性规则
    可用的状态转移路径：
      * --[人工处理完毕交回 AI 继续接待] (核实证据: handoff_ticket.status = resolved)--> 到达状态 s_answered (性质: 异常恢复)
🔒 全局不可绕过护栏规则：
  - 价格只能来自规则表，正品凭据只能来自知识库，禁止模型编造
  - 敏感功效问题只能走预审核白名单，白名单外一律保守+转人工
  - 知识库无命中时不允许硬答，保守答复并转人工
  - 转人工必须附「关注点+已答内容+未解决问题」摘要
  - 任何话术出口前必须过阶段校验，事实性措辞不得早于 deal_state.stage
  - 多模态识别文本只进不出，不作为回复内容直接外发
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【下单承接流】 满足条件【会话在 s_answered 状态且客户表达购买意向】，则受到影响：下单承接流启动，价格口径以本流规则表输出为准
  - 自身在该工作流时，若另一执行流 【试点守护流】 满足条件【本流产生首响超时、错价或转人工事件】，则受到影响：事件实时汇入试点看板，影响放量/回滚判定
### 执行流（Workstream）：下单承接流
描述：从客户咨询到人工完成核对、出单、揽收、运输的承接流，7 态与 DEAL_STAGE_ORDER 一一对应；AI 推进上限锁在待核对，其后每一步只能由人工客服执行
状态节点及迁移路径：
  - 状态：咨询中（consulting） (o_consulting)
    状态定义：客户仍在了解版本/价格/正品，尚未进入付款路径
    可用的状态转移路径：
      * --[AI 说明支付方式与发货口径（subIntent=payment_methods）] (核实证据: fulfillment 工具命中且 subIntent=payment_methods)--> 到达状态 o_awaiting_payment (性质: 正常迁移)
  - 状态：待付款（awaiting_payment） (o_awaiting_payment)
    状态定义：客户已获支付路径（微信/支付宝，企微内转账与红包均未开通），等待付款动作
    可用的状态转移路径：
      * --[客户表示已付款并发出付款截图（subIntent=payment_completed）] (核实证据: fulfillment 工具命中且 subIntent=payment_completed)--> 到达状态 o_awaiting_review (性质: 正常迁移)
  - 状态：待核对（awaiting_review） (o_awaiting_review)
    状态定义：已收到付款信息但订单未成立，必须由人工复述订单要素核对；这是 AI 可推进的最后一态
    可用的状态转移路径：
      * --[人工执行 confirm_review 确认核对] (核实证据: agent_operator 已复述姓名/电话/地址/规格/金额并确认)--> 到达状态 o_awaiting_shipment (性质: 正常迁移)
      * --[检测人工接管超时] (核实证据: 工单创建后超时无 taken_over 记录)--> 到达状态 o_intake_stalled (性质: 异常分支)
  - 状态：待出单（awaiting_shipment） (o_awaiting_shipment)
    状态定义：订单要素已核对，收款已确认，等待生成运单；此态起话术才可出现收款成功类措辞
    可用的状态转移路径：
      * --[人工执行 generate_tracking 生成模拟单号] (核实证据: deal_state.tracking_no 已生成)--> 到达状态 o_awaiting_pickup (性质: 正常迁移)
  - 状态：待揽收（awaiting_pickup） (o_awaiting_pickup)
    状态定义：运单已生成，等待快递揽收；此态起话术才可出现已发货/单号已出类措辞
    可用的状态转移路径：
      * --[人工执行 simulate_pickup 模拟揽收] (核实证据: 揽收动作已记录)--> 到达状态 o_picked_up (性质: 正常迁移)
  - 状态：已揽收（picked_up） (o_picked_up)
    状态定义：快递已取件；此态起话术才可出现已揽收类措辞
    可用的状态转移路径：
      * --[人工执行 simulate_transit 模拟运输] (核实证据: 运输状态已记录)--> 到达状态 o_in_transit (性质: 正常迁移)
  - 状态：运输中（in_transit） (o_in_transit)
    状态定义：包裹在途，承接流终态（Demo 范围内不含签收与售后）
  - 状态：承接搁置 (o_intake_stalled)
    状态定义：客户已付款但人工未及时接管，存在客诉与信任受损风险
    可用的状态转移路径：
      * --[升级值班客服完成补接管与核对] (核实证据: 升级提醒已发出且工单最终被人工接管)--> 到达状态 o_awaiting_review (性质: 异常恢复)
🔒 全局不可绕过护栏规则：
  - AI 不得确认收款成功或宣布订单生效，只有人工核对后订单才成立
  - nextStageFromCustomer 只在 fulfillment 工具命中时推进，只前进不后退，上限锁在 awaiting_review
  - awaiting_review 之后的每一步必须由 applyManualAdvance 执行，且严格按顺序，跨阶段一律拒绝
  - 订单要素必须经人工复述核对，AI 不能替客户跳过该动作
  - 发货只说时效口径（48h 发出/揽收后 1-3 天），不承诺具体到货日
  - 缺货档位（日版 15）不得进入承接流程
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【售前应答流】 满足条件【承接中客户追问价格/正品/风险类问题】，则受到影响：问题路由回售前应答流处理，承接流保持当前状态等待
  - 自身在该工作流时，若另一执行流 【试点守护流】 满足条件【本流完成人工核对（视为首单成交口径）】，则受到影响：成交数据汇入看板，支撑首单转化率计算
### 执行流（Workstream）：试点守护流
描述：小流量试点下持续观察首响/转人工/错价/转化指标，决定放量或回滚的守护流
状态节点及迁移路径：
  - 状态：小流量试点中 (p_piloting)
    状态定义：AI 仅承接小流量会话，看板按周汇总首响、自动接待率、错价与转化数据
    可用的状态转移路径：
      * --[确认连续观察期指标达标后放量] (核实证据: 转化率稳定于 9%~10% 健康区间且错价为零)--> 到达状态 p_scale_up (性质: 正常迁移)
      * --[触发回滚判定] (核实证据: 转化率连续两周低于健康区间，或出现错价事故)--> 到达状态 p_rollback (性质: 异常分支)
  - 状态：已放量 (p_scale_up)
    状态定义：试点验证通过，扩大 AI 承接流量比例，看板继续按周守护
    可用的状态转移路径：
      * --[放量后触发回滚判定] (核实证据: 放量期转化率连续两周低于健康区间)--> 到达状态 p_rollback (性质: 异常分支)
  - 状态：已回滚 (p_rollback)
    状态定义：AI 承接比例回退至人工为主，复盘错价/流失根因后再评估重启
    可用的状态转移路径：
      * --[完成根因修复后重启小流量试点] (核实证据: 复盘报告与知识库/规则表修复记录)--> 到达状态 p_piloting (性质: 异常恢复)
🔒 全局不可绕过护栏规则：
  - 转化率连续两周低于健康区间（9%~10%）必须回滚，不得侥幸续跑
  - 指标未经连续观察期验证不得放量
  - 出现错价事故须当日复盘，不等周度汇总
  - 回滚决策以看板口径为准，不接受个案好评作为放量依据
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【售前应答流】 满足条件【守护流进入 p_rollback 状态】，则受到影响：售前应答流 AI 承接范围收缩，会话优先路由人工
  - 自身在该工作流时，若另一执行流 【下单承接流】 满足条件【守护流进入 p_scale_up 状态】，则受到影响：承接流会话量随放量上升，需同步扩充人工核对班次
